# Content-First UI

## Purpose

Prevent visually polished but information-poor interfaces. Build interfaces
where the product's actual content, data, and functionality create the visual
interest.

## Rules

### 1. No decorative copy

Every visible string must serve at least one purpose:

- Identify an object, section, or action.
- Communicate information the user needs.
- Explain something otherwise ambiguous.
- Provide meaningful feedback or guidance.

Never introduce text solely to fill space, establish visual rhythm, or make a
screen feel polished.

Avoid:

- Inspirational or aspirational headlines.
- Generic descriptions of what a section does.
- Redundant subtitles.
- Decorative eyebrow labels.
- Repeated explanations of self-evident UI.
- Phrases such as "Your journey," "Discover more," "All in one place," or "Made
  for you" without a specific functional meaning.

### 2. Content owns the hierarchy

The most visually prominent elements should be the things users came to see or
manipulate.

Prioritize:

1. Primary content and user-generated information.
2. Important data and actionable controls.
3. Navigation and contextual information.
4. Supporting explanations.

Never allow decorative copy or container styling to compete with primary
content.

### 3. Fix weak layouts with structure, not filler

If an interface looks empty or unbalanced:

- Improve the layout of real content.
- Refine typography, spacing, and alignment.
- Adjust information density.
- Improve the representation of existing data.
- Remove unnecessary containers and section wrappers.

Do not add arbitrary text, cards, badges, icons, or decorative sections to
create visual interest.

### 4. Preserve product voice

Use precise, functional language appropriate to the product.

Prefer domain-specific terminology over generic product language. Don't invent
personality, brand messaging, or editorial copy unless explicitly requested.

### 5. Review before finishing

For every new or modified UI, ask:

- What information does each visible text element communicate?
- Could any text be deleted without losing meaning?
- Is the user's attention directed toward the most valuable content?
- Did I improve the primary UI, or merely decorate its surroundings?
- Would this interface still feel thoughtfully designed after removing all
  nonessential copy?

Remove or revise anything that fails these checks.

## Default behavior

When in doubt, omit rather than embellish. Prefer a quiet, precise, content-rich
interface over a visually elaborate but semantically empty one.
