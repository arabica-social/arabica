web/src/lib/components/Header.svelte renders `<div class="dropdown-menu">` conditionally with `{#if createOpen}` / `{#if userOpen}`, but the CSS in internal/web/assets/css/components/17-action-menu.css sets `.dropdown-menu { opacity: 0; pointer-events: none; }` and only `.dropdown-menu.is-open` is visible. The Svelte Header never adds `is-open`, so dropdowns render in the DOM but are invisible and unclickable.

Two fix options:
A) Add `class:is-open` to the dropdown-menu divs in Header.svelte (keeps the CSS animation).
B) Change the CSS so `.dropdown-menu` is visible by default and only the legacy `.is-open` toggle (used by DisclosureIsland on templ pages) gates it — but that would break templ pages that rely on the hidden-by-default behavior.

Option A is correct and minimal. Apply `class:is-open={createOpen}` and `class:is-open={userOpen}` to the two dropdown-menu divs. Add an E2E test that opens the Create dropdown and clicks an item (e.g. /roasters/new) to prove it works.
